PacmanHDL

Pac-Man built entirely in hardware: maze, four ghosts with their own chase rules, power pellets, fruit, breakable walls and five levels, all computed in SystemVerilog as the screen is scanned. There is no CPU and no frame buffer. What you play here is not a re-implementation. It is the actual RTL, simulated clock cycle by clock cycle with Verilator and compiled to WebAssembly, with the display output sampled into the canvas.

How this works

  1. The game core is the same RTL that is synthesized for the Tang Nano boards. It is checked frame by frame against a golden run recorded from the original DE10-Standard design.
  2. Verilator compiles it to C++, and Emscripten compiles that to WebAssembly. A Web Worker clocks the design one pixel at a time, about 320,000 cycles per frame, and samples the display signals (RGB, data enable, VSYNC) into the canvas the way a monitor would.
  3. Your keys become the same 8-button mask the board receives over USB-serial.

Originally a pair project in the Technion EE Lab 1A course (044157), then ported to open-source tools. Source: github.com/matanco64/PacmanHDL

Nothing is skipped: every clock cycle of the hardware is simulated. On most computers that is slower than the board's 73 frames per second, so the game runs in slow motion. The speed is shown under the screen.
